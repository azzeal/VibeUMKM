Sebelum datang

Malam sebelumnya, sekitar 45 menit
Kerjakan bagian ini sebelum hari workshop

Memasang Bun, Git, dan aplikasi AI butuh unduhan besar. Kalau ditunda ke hari H, waktu kelas habis untuk instalasi.

Laptop Windows atau MacBoleh memasang aplikasiKoneksi internetCharger

Pilih alat AI kamu

Alat AI adalah aplikasi yang menulis dan membetulkan kode atas perintahmu. Pilih satu, petunjuk di panduan ini ikut berubah. Tombol yang sama ada di kanan bawah.

Freebuff Desktop gratis, tanpa API key dan tanpa kartu kredit. Biayanya ditutup iklan teks.

OpenCode Desktop bersifat open source dan menyediakan model gratis bawaan. Model gratis bisa dibatasi atau berganti sewaktu-waktu.

Komputermu terdeteksi otomatis. Kalau salah, ganti Windows atau Mac di kanan bawah.

0.1Buat akun GitHub dan Vercel

GitHub

Daftar di github.com/signup, lalu verifikasi emailmu.

Vercel

Buka vercel.com/signup dan pilih Continue with GitHub.

Berhasil kalau

Kamu bisa membuka GitHub dalam keadaan login, dan dashboard Vercel terbuka.

0.2Pasang Git

Windows

Buka git-scm.com/install/windows, unduh pemasang 64-bit, lalu jalankan. Pertahankan pilihan bawaan, termasuk Git Credential Manager.

Mac

Buka git-scm.com/install/mac dan ikuti petunjuk di halaman itu.

Berhasil kalau

git --version menampilkan nomor versi. Login GitHub tidak diminta sekarang; jendela login muncul sendiri saat push pertama.

0.3Pasang Bun

Langkah

Buka PowerShell (cari di menu Start), tempel perintah di bawah, lalu tekan Enter. Tunggu sampai selesai.

irm bun.sh/install.ps1 | iex
Kalau diblokir

Muncul pesan kebijakan eksekusi? Jalankan Set-ExecutionPolicy -Scope CurrentUser RemoteSigned, jawab Y, lalu ulangi perintah di atas.

Langkah

Buka Terminal dan jalankan perintah di bawah, lalu tekan Enter.

curl -fsSL https://bun.sh/install | bash
Berhasil kalau

Tutup lalu buka lagi Terminal atau PowerShell, jalankan bun --version, dan muncul nomor versi.

0.4Pasang editor dan alat AI

Editor

Pasang Visual Studio Code. Kamu akan sering melihat file yang diubah AI di sini.

Alat AI

Buka freebuff.com/desktop, unduh versi untuk komputermu, lalu pasang.

Alat AI

Buka opencode.ai/download, unduh aplikasi desktop, lalu pasang.

Berhasil kalau

Aplikasi alat AI terbuka dan menampilkan layar awal.

Kalau gagal

Peringatan keamanan saat membuka aplikasi? Lihat bagian 10. Kalau tetap tidak jalan, ganti alat AI lewat tombol kanan bawah.

1

Aturan dan pengaman

Kali ini kamu tidak membuat aplikasi dari nol. Kamu merawat aplikasi orang lain: memperbaiki tampilan, membetulkan bug, dan menutup celah keamanan. Perananmu adalah pengambil keputusan dan pemeriksa, AI yang mengetik kodenya.

Commit kecil, sering

Satu perbaikan, satu commit. Kalau AI merusak sesuatu, kamu bisa kembali ke versi terakhir yang jalan.

Rahasia tidak masuk repo

.env.local berisi kunci sesi. File itu tidak boleh ikut ter-commit, dan repo publik berarti siapa pun bisa membacanya.

Klien tidak dipercaya

Validasi dan izin harus ada lagi di server. Memeriksa di browser saja bukan keamanan, hanya kenyamanan.

Satu tugas, satu prompt

Jangan minta AI mengerjakan revamp, fix, dan security sekaligus. Periksa hasil tiap langkah sebelum lanjut.

Repo ini adalah versi contoh

Sebagian kode di repo contoh sudah benar. Tugasmu adalah memastikan perilakunya benar di salinanmu, bukan menyalin mentah: baca, uji di browser, dan pahami alasannya.

2

Siapkan proyek

Sekitar 25 menit
Tampilan aplikasi bisa sedikit berbeda

Nama tombol dan menu bisa berubah mengikuti versi. Cari yang artinya paling dekat, atau minta fasilitator menunjukkan layarnya.

2.1Ambil salinan dari template, lalu clone

Pakai template

Buka github.com/azzeal/tanstack_ekraf, klik Use this template → Create a new repository. Ini membuat repo baru milikmu, bukan fork, jadi riwayatnya bersih.

Isi form

Nama repo [nama-folder], pilih Public, lalu klik Create repository.

Clone

Di halaman repo barumu klik Code dan salin alamatnya. Lalu buka folder Documents, klik kanan di area kosong, pilih Open Git Bash here (Windows) atau buka Terminal (Mac), dan jalankan tiga perintah berikut.

git clone https://github.com/[username GitHub]/[nama-folder].git
cd [nama-folder]
bun install
Berhasil kalau

Folder proyek muncul di Documents, bun install selesai tanpa tulisan merah, dan git remote -v menunjuk ke repo milikmu sendiri.

Catatan fasilitator

Supaya tombol Use this template muncul di repo asal, buka Settings repo itu dan centang Template repository.

2.2Buat file .env.local

Kenapa

Aplikasi butuh alamat dasar dan kunci sesi. Tanpa keduanya, login akan gagal.

Buat kunci

Jalankan perintah ini di folder proyek, lalu salin hasilnya.

bun x @better-auth/cli secret
Isi file

Buat file bernama .env.local di folder utama proyek, isinya dua baris berikut.

BETTER_AUTH_URL=http://localhost:3000
BETTER_AUTH_SECRET=tempel-hasil-di-atas
Jangan

Jangan pernah menempelkan isi .env.local ke chat AI atau ke GitHub. File itu sudah masuk .gitignore, biarkan begitu.

Berhasil kalau

File .env.local ada di folder proyek dan berisi dua baris itu.

2.3Jalankan aplikasinya

bun dev
Buka

Kunjungi http://localhost:3000 di browser.

Berhasil kalau

Halaman awal aplikasi terbuka tanpa layar error. Biarkan terminal itu tetap berjalan selama kamu bekerja.

Kalau port dipakai

Hentikan dengan Ctrl+C di terminal, jalankan lagi, atau minta AI memakai port lain.

2.4Seed admin lalu login

Seed

Buka http://localhost:3000/setup dan klik Seed Admin Account. Perintah ini membuat akun admin dan beberapa produk contoh.

Login

Buka /login, masuk dengan email admin@example.com dan password admin12345.

Berhasil kalau

Kamu masuk ke /dashboard dan melihat sidebar dengan menu Dashboard, Products, dan Users.

Ingat

Tidak ada database permanen. Data hilang setiap server restart, jadi ulangi seed setelah restart atau setelah deploy.

2.5Buat branch kerja

git checkout -b revamp-[username GitHub]
Kenapa

Semua perubahanmu masuk ke branch ini, bukan ke main. Nanti branch ini yang jadi Pull Request.

Berhasil kalau

git status menyebut nama branch barumu.

3

Peta kode dan rencana

Sekitar 30 menit

Sebelum mengubah apa pun, pahami dulu letak bagian-bagiannya. Aplikasi ini memakai TanStack Start: setiap file di src/routes otomatis menjadi halaman, dan semua penulisan data lewat server function.

3.1Baca peta repo

LetakIsinya
src/routes/Semua halaman. Halaman admin ada di bawah layout _admin.tsx yang menjaga login dan memasang sidebar.
src/lib/auth.tsKonfigurasi Better Auth: sesi, cookie, dan origin yang dipercaya.
src/lib/session.tsrequireAuth() dan requireAdmin() yang dipakai server function.
src/lib/server/Server function: produk, pengguna, dan penanganan error.
src/components/Komponen tampilan, termasuk ProductFormModal dan UserRoleModal.
src/components/ui/Komponen shadcn: button, dialog, input, select, dan lainnya.
Yang perlu diingat

routeTree.gen.ts dibuat otomatis. Setiap kali menambah atau menghapus file route, jalankan bunx tsr generate.

3.2Telusuri empat halaman

Langkah

Dengan aplikasi berjalan, buka /dashboard, /products, /users, dan /login. Catat tiga hal: yang sudah bagus, yang rusak, dan yang membingungkan.

Coba juga

Kecilkan jendela browser selebar HP, lalu lihat halaman mana yang berantakan. Buka /products dan coba isi kolom form produk.

Berhasil kalau

Kamu punya daftar minimal 5 temuan nyata, bukan dugaan.

3.3Tulis rencanamu di kotak ini

Langkah

Ganti semua teks dalam tanda kurung siku. Tulisanmu tersimpan otomatis di browser ini.

Simpan jadi file

Tempel hasil salinan ke chat alat AI. Kalimat pembuka yang ikut tersalin meminta AI membuat RENCANA.md di folder proyek.

Berhasil kalau

File RENCANA.md muncul di folder proyek dan isinya sama dengan tulisanmu.

3.4Periksa rencanamu

  • Ada minimal 3 halaman yang akan dirapikan, dengan alasan masing-masing.
  • Ada minimal 1 bug yang akan dibetulkan, lengkap dengan cara memunculkannya.
  • Ada minimal 2 perbaikan keamanan: satu soal izin, satu soal validasi di server.
  • Tidak ada tanda kurung siku yang tersisa, dan tidak ada rahasia yang ditulis.
Berhasil kalau

Temanmu membaca rencana itu dan bisa menebak hasil akhirnya tanpa bertanya.

4

Revamp tampilan

Sekitar 90 menit

Target: minimal tiga halaman terasa seperti produk sungguhan, bukan proyek contoh. Kerjakan satu bagian, lihat hasilnya di browser, baru lanjut.

4.1Rapikan sidebar dashboard

Prompt
Baca src/routes/_admin.tsx dan komponen sidebar-nya. Rapikan tampilan sidebar: beri ikon lucide-react untuk tiap menu, tandai menu yang sedang aktif, dan buat bisa dilipat. Di layar HP, sidebar menjadi laci yang dibuka lewat tombol hamburger. Jangan ubah logika penjagaan login.
Berhasil kalau

Menu aktif terlihat jelas, ikon muncul, dan di lebar 400px sidebar tidak menutupi isi.

4.2Poles modal produk dan modal peran

Prompt
Modal ProductFormModal dan UserRoleModal sudah memakai dialog shadcn. Poles keduanya: tampilkan pesan validasi di bawah kolom, nonaktifkan tombol simpan saat menyimpan, tampilkan status memuat, dan pastikan tombol Batal menutup tanpa menyimpan. Jangan mengganti komponen ui/ yang sudah ada.
Uji

Buka /products, klik tombol tambah produk, kosongkan satu kolom, lalu simpan. Pesan kesalahan harus muncul di kolom itu, bukan di console.

4.3Desain ulang halaman login

Prompt
Desain ulang halaman /login menjadi kartu masuk yang bersih dan modern: terpusat, ada judul dan logo sederhana, bayangan halus, mendukung mode gelap, dan pesan kesalahan yang jelas saat email atau password salah. Jangan tampilkan pesan yang membocorkan apakah email terdaftar. Pertahankan fungsi login yang sudah ada.
Uji

Coba password salah, pastikan pesannya jelas dan tidak menyebut akun mana yang keliru. Coba juga mode gelap lewat tombol tema.

4.4Tambah input gambar produk

Aturan

Gambar disimpan sebagai data URL, sisi terpanjang maksimal 512 px, hanya PNG, JPEG, WebP, atau GIF. Batas panjang data URL 400.000 karakter.

Prompt
Tambahkan input gambar di modal produk: pilihan file dan kolom URL, lengkap dengan pratinjau. Sebelum disimpan, perkecil gambar di browser agar sisi terpanjang maksimal 512px, dan tolak tipe selain image/png, image/jpeg, image/webp, image/gif. Tampilkan pesan bila gambar terlalu besar. Ingat: pemeriksaan di browser hanya untuk kenyamanan.
Uji

Unggah foto besar dari HP, simpan, lalu buka detail produk. Gambar harus tampil dan ukurannya sudah diperkecil.

4.5Hapus halaman demo

Prompt
Hapus semua route demo dan halaman scaffold yang tidak dipakai produk ini (folder src/routes/demo, route about, dan sejenisnya). Setelah dihapus, jalankan bunx tsr generate, lalu pastikan tidak ada tautan mati di Header, Footer, atau __root.tsx. Tampilkan daftar file yang kamu ubah.
Berhasil kalau

Tidak ada tautan yang berakhir 404, dan bun dev tetap berjalan tanpa error.

4.6Responsif dan keadaan data

Prompt
Pastikan semua halaman admin nyaman di lebar 400px: tabel tidak boleh melebar keluar layar, gunakan kartu atau gulir horizontal yang rapi. Tambahkan keadaan memuat, kosong, dan gagal pada halaman yang mengambil data. Gunakan Tailwind dan komponen ui/ yang ada.
Uji

Hemat data ke keadaan kosong dengan menghapus semua produk, lalu lihat pesannya. Matikan server sebentar untuk melihat keadaan gagal.

4.7Catat prompt yang berhasil

Prompt
Tambahkan catatan ke file PROMPT-LOG.md (buat bila belum ada). Isinya: prompt perbaikan saya yang terakhir, apa hasilnya, dan apakah perlu diulang. Tulis dalam bahasa Indonesia yang sederhana.
Berhasil kalau

PROMPT-LOG.md berisi minimal 3 catatan sebelum kamu mengumpulkan.

5

Perbaiki error

Sekitar 60 menit

Bagian ini menilai cara kamu membaca pesan error, bukan kecepatan menebak. Selalu tempel pesan aslinya ke AI, jangan diringkas.

5.1Jalankan lint dan betulkan

bun run lint
Prompt
Ini hasil bun run lint di proyek ini:

[tempel keluaran lengkap]

Betulkan satu per satu dari yang paling sedikit risikonya. Jelaskan tiap perubahan dalam satu kalimat. Jangan mengubah perilaku aplikasi hanya demi menghilangkan peringatan.
Berhasil kalau

Perintah lint selesai tanpa error baru. Peringatan sisa dari scaffold boleh ada asal kamu bisa menjelaskannya.

5.2Kolom form produk tidak bisa diketik

Gejala

Di modal tambah atau edit produk, kolom nama, deskripsi, harga, dan stok menolak ketikan.

Prompt
Di modal produk, semua kolom tidak bisa diketik. Periksa src/components/ProductForm.tsx: pastikan setiap input adalah controlled input yang benar, dengan value dari field.state.value dan onChange yang memanggil field.handleChange(event.target.value), serta tidak ada key yang membuat form ter-mount ulang di setiap ketikan. Jelaskan penyebabnya sebelum memperbaiki.
Uji

Ketik nama produk, tab ke kolom harga, lalu simpan. Semua isi harus tetap ada setelah modal ditutup dan dibuka lagi.

5.3Build harus bersih

bun run build
Prompt
Build gagal dengan pesan ini:

[tempel pesan]

Cari akar masalahnya, bukan hanya membungkam error dengan any atau @ts-ignore. Setelah beres, jalankan bun run build lagi dan tunjukkan hasilnya.
Berhasil kalau

Build selesai tanpa error, dan bun dev masih bisa dijalankan.

5.4Uji semua route secara manual

RouteHarus terjadi
/, /login, /setupTerbuka tanpa login. Seed aman dijalankan dua kali.
/dashboardDialihkan ke login saat belum masuk. Sidebar tampil setelah masuk.
/productsDaftar produk tampil, urutannya bisa diubah, modal tambah, edit, dan hapus bekerja.
/usersHanya admin. Peran bisa diganti, admin terakhir tidak bisa dihapus.
Berhasil kalau

Semua baris di tabel itu kamu coba sendiri, bukan diasumsikan.

5.5Tiga jebakan khas TanStack

  • useParams() wajib diberi asal route, misalnya useParams({ from: "/products/$productId" }). Tanpa itu, halaman error.
  • createServerFn hanya mendukung GET dan POST. Jangan memakai PATCH atau DELETE; tulis maksudnya di body.
  • Setiap menambah atau menghapus file route, jalankan bunx tsr generate supaya routeTree.gen.ts ikut berubah.
Kalau ragu
Jelaskan dengan bahasa sederhana cara kerja file-based routing di TanStack Router pada proyek ini, lalu tunjukkan satu contoh menambah route baru yang butuh parameter.
6

Perkuat keamanan

Sekitar 75 menit
Minimal dua perbaikan, satu dari tiap kolom

Pilih satu dari izin akses dan satu dari pengerasan aplikasi. Setiap perbaikan wajib kamu jelaskan: serangan apa yang dicegah.

6.1Audit izin di setiap server function

Prompt
Periksa semua server function di src/lib/server/ dan route API. Buat tabel: nama function, apakah memanggil requireAuth atau requireAdmin, dan apakah alasannya tepat. Jangan ubah kode dulu, cukup laporkan yang belum dijaga.
Lalu

Minta AI menambahkan penjagaan yang kurang, satu function per prompt, lalu uji dengan logout: setiap aksi tulis harus ditolak.

Berhasil kalau

Tidak ada aksi tulis yang bisa dijalankan tanpa sesi, dan tidak ada aksi admin yang bisa dijalankan pengguna biasa.

6.2Cegah admin mengunci dirinya sendiri

Prompt
Di server function updateUserRole dan deleteUser, tolak perubahan yang membuat admin menurunkan perannya sendiri atau menghapus akunnya sendiri. Tolak juga penghapusan admin terakhir. Kembalikan pesan error yang jelas. Tambahkan juga pemeriksaan yang sama di tampilan agar tombolnya nonaktif, tetapi tetap tegakkan di server.
Uji

Masuk sebagai admin, coba ubah peranmu sendiri jadi user, lalu coba hapus akunmu. Keduanya harus ditolak.

6.3Batasi percobaan login

Prompt
Tambahkan pembatasan percobaan login: maksimal 5 kegagalan per alamat IP dalam 15 menit, lalu tolak sementara dengan pesan yang sopan. Gunakan src/lib/rate-limit.ts yang sudah ada. Pastikan penghitungnya tidak bisa dilewati dengan mengganti header. Jelaskan batasannya dan risikonya di komentar singkat.
Uji

Coba login dengan password salah 6 kali. Percobaan keenam harus ditolak, dan login dengan password benar sesudahnya juga ditolak sampai waktunya habis.

6.4Validasi ulang di server dengan Zod

Prompt
Pastikan setiap server function memvalidasi inputnya dengan Zod di server, memakai .strict() agar kolom asing ditolak. Periksa juga batas panjang teks, harga dan stok tidak negatif, serta id harus berupa string yang ada. Jangan mengandalkan validasi di form saja. Tunjukkan satu contoh request yang sekarang ditolak.
Berhasil kalau

Mengirim kolom tambahan seperti id atau createdAt dari klien ditolak, bukan diterima diam-diam.

6.5Cookie sesi dan kebocoran rahasia

Prompt
Periksa konfigurasi sesi di src/lib/auth.ts. Pastikan cookie httpOnly, sameSite lax, secure hanya di produksi, dan ada masa berlaku sesi yang wajar. Lalu cari di seluruh repo: kunci rahasia yang ditulis langsung di kode, file .env yang ikut ter-commit, dan pemakaian dangerouslySetInnerHTML dengan data pengguna. Laporkan temuan dan usulkan perbaikannya.
Berhasil kalau

git status tidak menampilkan .env.local, dan tidak ada rahasia di file yang masuk repo.

6.6Tulis alasan keamanannya

Prompt
Buat file SECURITY-NOTES.md. Untuk setiap perbaikan keamanan yang saya lakukan, tulis: nama perbaikan, file yang diubah, serangan yang dicegah, dan cara mengujinya dalam satu langkah. Bahasa Indonesia, maksimal dua kalimat per poin.
Berhasil kalau

Setiap perbaikan punya penjelasan yang bisa kamu bacakan saat demo.

7

Pull request

Sekitar 25 menit
Semua lewat terminal

Langkah 7.1 sampai 7.3 memakai perintah git dan selalu bisa dipakai. Langkah 7.4 meminta AI yang menjalankan commit dan push.

7.1Commit perubahan

Periksa dulu

Jalankan git status. Pastikan .env.local tidak muncul di daftar file yang akan di-commit.

git add .
git commit -m "revamp tampilan, perbaikan bug, dan penguatan keamanan"
Berhasil kalau

git log --oneline -1 menampilkan commit barumu.

Kebiasaan

Satu perbaikan selesai, satu commit. Pisahkan revamp, fix, dan security supaya mudah ditinjau.

7.2Push branch dan buka Pull Request

git push -u origin revamp-[username GitHub]
Login sekali saja

Push pertama membuka jendela Git Credential Manager. Pilih Sign in with your browser, setujui akses, lalu kembali ke terminal. Setelah ini kamu tidak ditanya lagi.

Buka PR

Buka repo-mu di GitHub. Setelah branch ter-push, muncul banner Compare & pull request. Kalau tidak muncul, buka tab Pull requests → New pull request, pilih base main dan compare branch kerjamu.

Isi PR
Tugas A (revamp): [3 halaman yang diubah dan alasannya]
Tugas B (fix): [bug yang dibetulkan dan cara memunculkannya]
Tugas C (security): [perbaikan yang dipilih dan serangan yang dicegah]
Bukti: [link Vercel]
Berhasil kalau

Pull Request terbuka, tanpa konflik, dan semua commit terlihat di tab Commits.

7.3Tulis NOTES.md

Prompt
Buat NOTES.md berisi satu paragraf: apa yang sempat rusak saat saya mengerjakan tugas ini, bagaimana saya menemukannya, dan bagaimana saya memperbaikinya. Jujur dan spesifik, sebutkan nama file.
Berhasil kalau

NOTES.md ada di repo dan isinya bukan kalimat umum seperti "semua berjalan lancar".

7.4Minta AI yang commit dan push

Siapkan

Buka Integrations di Freebuff, pilih GitHub, lalu Connect. Untuk commit dari komputermu, Freebuff memakai Git dan kredensial yang sudah tersimpan di komputer.

Siapkan

OpenCode Desktop memakai Git dan kredensial di komputermu, jadi tidak ada tombol connect terpisah. Pastikan push manual di langkah 7.2 sudah pernah berhasil.

Cek dulu
Jalankan git status dan git remote -v, lalu jelaskan hasilnya dengan bahasa sederhana. Jangan ubah file apa pun.
Prompt
Commit semua perubahan dengan pesan "revamp, fix, dan security", lalu push ke branch revamp-[username GitHub]. Setelah selesai tampilkan git log --oneline -3.
Jangan

Jangan pernah menempelkan token atau password ke chat. Kalau AI memintanya, hentikan dan push sendiri lewat terminal.

8

Deploy ke Vercel

Sekitar 20 menit

8.1Impor repo

Langkah

Di vercel.com klik Add New → Project, pilih repo milikmu ([username GitHub]/[nama-folder]), lalu Import. Biarkan pengaturan framework terdeteksi otomatis sebagai TanStack Start.

Kalau repo tidak muncul

Klik Adjust GitHub App Permissions, izinkan akses ke repo itu, lalu kembali.

8.2Isi environment variable

Langkah

Sebelum menekan Deploy, buka Environment Variables dan tambahkan dua baris berikut.

BETTER_AUTH_URL=https://[nama-folder].vercel.app
BETTER_AUTH_SECRET=[kunci baru dari bun x @better-auth/cli secret]
Penting

Jangan memakai kunci yang sama dengan .env.local untuk produksi. Buat kunci baru, simpan di tempat aman, jangan di repo.

Berhasil kalau

Dua variabel itu terdaftar untuk environment Production.

8.3Deploy dan seed ulang

Deploy

Klik Deploy dan tunggu sampai selesai. Catat alamat yang berakhiran .vercel.app, lalu tempel ke kolom Link Vercel di panel "Isi data kamu".

Seed

Buka /setup di alamat produksi dan klik Seed Admin Account, lalu login dengan akun admin yang sama.

Ingat

Data hanya hidup di memori instance. Setiap deploy baru atau instance dingin akan mengosongkannya, jadi seed ulang bila perlu saat demo.

Kalau 500

10

Jika tersangkut

Tempel pesan error apa adanya ke AI, itu petunjuk terbaiknya. Kalau buntu lebih dari 10 menit, angkat tangan dan panggil fasilitator.

"Windows protected your PC" saat membuka pemasang

Peringatan standar Windows untuk aplikasi baru. Kalau file itu kamu unduh dari situs resmi di panduan ini, klik More info, lalu Run anyway.

Aplikasi "tidak bisa dibuka karena dari developer yang tidak dikenal" (Mac)

Klik kanan ikon aplikasinya di folder Applications, pilih Open, lalu Open sekali lagi.

bun: command not found

Bun sudah terpasang tetapi Terminal belum mengenalnya. Tutup Terminal atau PowerShell, buka lagi, lalu jalankan bun --version. Kalau tetap gagal, pasang ulang Bun dan pastikan folder .bun/bin masuk PATH.

Aplikasi menolak login, muncul INVALID_ORIGIN

Alamat di BETTER_AUTH_URL tidak sama dengan alamat yang kamu buka. Kalau membuka 127.0.0.1, ganti isinya ke http://localhost:3000, atau sebaliknya. Di produksi, isinya harus alamat .vercel.app yang sebenarnya.

Error "Invalid secret" atau sesi langsung hilang

BETTER_AUTH_SECRET kosong atau berubah. Buat kunci baru dengan bun x @better-auth/cli secret, isi ulang .env.local, lalu hentikan dan jalankan lagi bun dev.

Halaman baru tidak muncul, atau muncul error routeTree
bunx tsr generate

Setelah itu hentikan dan jalankan lagi bun dev. File routeTree.gen.ts memang dibuat otomatis, jangan diedit manual.

Kolom form tetap tidak bisa diketik

Pastikan nilai input memakai field.state.value dan onChange memanggil field.handleChange. Kalau modal memakai key yang berubah tiap render, form akan ter-mount ulang dan ketikan hilang.

Tunjukkan bagian ProductForm.tsx yang mengatur value dan onChange untuk kolom nama, lalu jelaskan kenapa ketikan bisa hilang di proyek ini.
Port 3000 sudah dipakai

Hentikan proses lain dengan Ctrl+C di terminal yang menjalankan aplikasi. Kalau masih dipakai, jalankan dengan port lain, misalnya bun dev --port 3001, lalu sesuaikan BETTER_AUTH_URL.

Data hilang setiap restart

Itu memang rancangan proyek ini: tidak ada database, data hidup di memori. Jalankan /setup lagi setelah restart atau deploy. Jangan menambahkan database kecuali diminta.

Vercel menampilkan 500 setelah deploy

Buka Deployments → Functions → Logs. Penyebab tersering: environment variable belum diisi, BETTER_AUTH_URL masih localhost, atau build gagal karena lint.

AI merusak hasil yang tadinya bagus

Batalkan semua perubahan yang belum di-commit dengan perintah di bawah. Perubahan yang sudah ter-commit tetap aman.

git restore .
Push meminta login atau muncul "Authentication failed"

Jendela Git Credential Manager terbuka saat push pertama. Pilih Sign in with your browser dan setujui akses. Kalau jendelanya tidak muncul, jalankan git credential-manager configure lalu push lagi. Di Mac, gunakan Personal Access Token sebagai password bila diminta.

Perubahan saya tidak muncul di Pull Request

Kamu mungkin commit di branch lain. Jalankan git branch --show-current, pastikan hasilnya branch kerja yang benar, lalu push lagi. Bandingkan juga dengan tab Commits di halaman PR.
